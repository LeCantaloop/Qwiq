## Summary

Investigated and documented fix for CS0006 "Metadata file not found" errors occurring in GitHub Actions CI builds. Created comprehensive task plan using multiple subagents for research and review.

## What Was Done

### 1. Root Cause Analysis

Analyzed failing CI run 20109171974 which showed CS0006 errors:

```text
CSC : error CS0006: Metadata file 'obj/Release/ref/Qwiq.Core.dll' could not be found
```

**Key Finding**: The `/m:1` flag only limits solution-level parallelism, NOT inner-build parallelism within multi-TFM projects. MSBuild's `DispatchToInnerBuilds` runs net472 and net8.0 inner builds in parallel, causing reference assembly race conditions.

### 3. Fix Already Implemented

Discovered the fix was already present in `Directory.Build.props` (lines 88-96):

```xml
<PropertyGroup>
  <BuildInParallel>false</BuildInParallel>
  <MSBuildBuildInParallel>false</MSBuildBuildInParallel>
  <ProduceReferenceAssembly>false</ProduceReferenceAssembly>
</PropertyGroup>
```

Also present in `Directory.Build.rsp`:

```text
/m:1
/nodeReuse:false
-p:BuildInParallel=false
-p:MSBuildBuildInParallel=false
-p:ProduceReferenceAssembly=false
```

### 4. Added .NET Framework Reference Assemblies

Added `Microsoft.NETFramework.ReferenceAssemblies` package to enable building net472 targets on Linux:

**Directory.Packages.props**:

```xml
<PackageVersion Include="Microsoft.NETFramework.ReferenceAssemblies" Version="1.0.3" />
```

**Directory.Build.props**:

```xml
<ItemGroup Condition="'$(TargetFramework)' == 'net472'">
  <PackageReference Include="Microsoft.NETFramework.ReferenceAssemblies" PrivateAssets="All" />
</ItemGroup>
```

This is the officially recommended way to build .NET Framework targets on non-Windows without the SDK.

## Decisions Made

### Decision 1: Disable Inner-Build Parallelism Globally (Not CI-Only)

- **Rationale**: The fix was applied globally (not just CI) in `Directory.Build.rsp` and `Directory.Build.props` because local builds also benefit from deterministic behavior
- **Tradeoff**: Slightly slower builds (~10-20%) for reliability

### Decision 2: Use Directory.Build.props for Reference Assemblies

- **Rationale**: Centralized approach instead of per-project changes
- **Benefit**: All projects targeting net472 automatically get the package

### Decision 3: PrivateAssets="All" for Reference Assemblies

- **Rationale**: This is a build-time only dependency
- **Benefit**: Won't pollute consumer NuGet packages

## Lessons Learned

1. MSBuild has multiple parallelism levels - `/m:1` only affects solution-level, not inner-build
2. Reference assemblies are the source of CS0006 race conditions in multi-TFM builds
3. `Microsoft.NETFramework.ReferenceAssemblies` enables cross-platform net472 builds
4. Directory.Build.props is the right place for cross-cutting build concerns
