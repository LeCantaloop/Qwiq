### W2.16 Phase 1 - REST Unit Tests with WireMock.Net

**Status**: 🔄 In Progress
**Priority**: HIGH
**Effort**: M (12-19 hours)

**What was done**:

1. Added WireMock.Net 1.5.40 to Directory.Packages.props
2. Added Moq 4.16.0 + Moq.Analyzers 0.4.0 to Directory.Packages.props
3. Verified no security vulnerabilities in new packages
4. Analyzed existing REST client structure (WorkItemStore, WorkItemStoreFactory)

**Decisions made**:

- **Decision**: Add packages to existing Qwiq.Core.UnitTests project instead of creating new project
- **Rationale**: Keeps test organization simple, follows existing structure, RestUnit category will distinguish from other tests

**Next steps**:

- Add WireMock.Net reference to Qwiq.Core.UnitTests.csproj
- Create test fixtures for REST client with WireMock
- Implement query execution tests
- Add CI integration for RestUnit tests

**Challenges encountered**:

- **Challenge**: REST client is tightly coupled to Azure DevOps SDK (VssConnection)
- **Analysis**: The WorkItemStoreFactory creates a VssConnection directly with the endpoint URL, making it difficult to inject a WireMock server URL for testing
- **Root cause**: Factory pattern uses static singleton (TfsConnectionFactory.Default) that doesn't allow URL injection
- **Impact**: Cannot easily test REST client without significant refactoring

**Considered approaches**:

1. **Mock VssConnection with Moq**: Complex due to sealed classes and async methods in Azure DevOps SDK
2. **HTTP proxy with WireMock**: Requires changing VssConnection settings to use proxy
3. **Refactor for dependency injection**: Cleanest solution but requires API surface changes
4. **Test at integration level only**: Current state - not ideal for CI

**Decision**: Create ADR documenting the testing challenge and propose refactoring approach for future work. Mark W2.16 Phase 1 as "infrastructure complete, implementation deferred pending architectural decision".
